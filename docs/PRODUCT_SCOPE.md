# 产品范围与角色

## 产品定位

Aisenedu 是一个面向教育场景的 Web 工具平台，目标是把教师、家长和学生在教学、学习与家庭协同中的高频工作集中到清晰、可复用的工具中。

## 当前范围

- 当前交付平台：Web。
- 当前阶段：基础工程和产品边界建设。
- 当前重点：建立可持续扩展的业务模块、权限模型和服务边界。
- 桌面端、移动端、原生应用和复杂 AI 能力：暂不作为默认范围，需由具体需求单独确认。

## 用户角色

### 教师

可能需要课程/班级管理、备课与资料整理、作业与评价、教学过程记录和家校沟通工具。

### 家长

可能需要查看孩子的学习任务与反馈、家庭学习安排、与教师沟通和成长记录工具。

### 学生

可能需要查看学习任务、提交作业、获取反馈、整理学习资源和追踪学习进度。

### 平台管理员

负责平台配置、用户与组织管理、权限治理、内容审核和运行监控。管理员能力必须通过服务端权限再次校验。

## 业务模块演进方向

以下是架构预留的模块方向，不代表全部都已实现：

| 模块 | 主要职责 |
| --- | --- |
| `auth` | 登录、会话、角色和权限入口 |
| `teacher` | 教师工作台、班级和教学工具 |
| `parent` | 家长工作台、家庭协同和反馈查看 |
| `student` | 学生工作台、任务和学习进度 |
| `course` | 课程、班级、章节或学习单元 |
| `assessment` | 作业、测验、评价和反馈 |
| `resource` | 教学/学习资料管理和共享 |
| `analytics` | 面向不同角色的学习与教学数据汇总 |

## 产品约束

- 不默认把所有角色塞进同一套复杂页面；页面和功能应围绕角色任务组织。
- 学生数据遵循最小权限原则，展示和导出必须有明确授权。
- 业务模块先定义核心任务和数据边界，再扩展通知、协作和自动化能力。
- 任何具体模块上线前补充其用户故事、权限矩阵、数据模型和验收标准。

## 待决事项

- 是否支持多学校/多组织租户。
- 教师、家长和学生之间的绑定方式。
- 首个正式 MVP 模块及其数据保留周期。
- 是否需要接入第三方身份、消息或支付服务。
